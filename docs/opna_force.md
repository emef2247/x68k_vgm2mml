# Partial conversion for listening (--force)

Japanese original: [opna_forceJ.md](opna_forceJ.md).

`--force` explicitly permits the documented losses so that supported MML and
listening artifacts can be generated even while conversion support is incomplete.
It is disabled by default and is available in `vgm2mml.py` and
`scripts/export_mdx.py`.

The OPNA -> OPM -> MDX route can omit unsupported hardware effects. The native
OPM/supported PCM and OPM + SegaPCM routes can also omit PDX samples that exceed
capacity. Force also applies to the standalone PSG -> OPM route: PSG and SSG
share the same projection for omitting unsupported noise/hardware-envelope
intervals. At this stage it does not bypass corrupt input, unresolved source
evidence, unsupported source routes/streams, invalid clocks, missing external
tools, or compiler limits.

```bash
python scripts/export_mdx.py input.vgm \
  --outdir outputs/listen/forced --no-vgm \
  --compiler mmlx --pcm-policy best-effort --force
```

## Unsupported hardware effects

| Source | Output with force |
|---|---|
| Unclassified OPNA register effects | Record the original write and omit its target effect |
| PSG/SSG noise and hardware envelopes | Mute unsupported intervals outside [limited noise-only support](psg_musical_noise.md); emit supported intervals |
| CH3 special frequencies / CSM | Output-gate only CH3 during affected intervals; other channels continue |
| FM operator SSG-EG | Output-gate the affected channel while enabled |
| SSG parts without an OPM channel allocation | Keep the existing FM-priority allocation and report omitted part names and reasons |
| Previously unprojected controls such as rhythm and IRQ | Include them in the omission list |
| Existing approximations such as LFO | Report them as approximations, separately from omitted writes |
| Unsupported DELTA controls, including known repeat/recording modes | Omit the whole PCM part and continue FM/SSG |

Normal key, voice, and ordinary pitch projection continues while FM output is
gated. Output resumes using the retained normal key state without adding a
synthetic Key-On. CSM automatic keys and the original EG phase are not
reconstructed. This is an explicit listening approximation.

Supported held DELTA volume, pan, and rate changes continue through their existing
route. PCM is not generated by ignoring missing source data, unknown diagnostics,
corrupt state, or broken source evidence.

An "unmapped operator slot" does not mean that no write occurred. It denotes an
address whose channel field is 3 in the ordinary FM operator layout, where valid
channel fields are 0..2: for example, `0x83` after `0x80/81/82`. A VGM can contain
writes to that address. They remain in the original evidence and are omitted
from the target projection under force. Other unclassified registers are not
assumed universally safe either: the list records that their unsupported effects
were omitted. Register-layout implementation reference:
[ymfm](https://github.com/aaronsgiles/ymfm/blob/main/src/ymfm_opn.h).
This does not establish that every undocumented physical-chip effect has been
validated.

## PCM capacity

The default `--pcm-bank-merge budget96` first reuses existing target assets to
fit both 96 slots and a 1,200,000-byte PDX, including its table. This approximation
is separate from force. With `similar` / `off`, or for routes outside this
reducer, force may omit a whole new sample that would exceed the file budget
(`pdx_byte_capacity`); later events using retained samples still play. It does
not crop bytes or infer new decoder reset boundaries. Final packed size is
checked even after capacity selection. See [bank reduction](pcm_bank_reduction.md).

Keep the original PCM IR unchanged and select target samples in first-playback
order.

- At most 96 samples per bank. Once full, omit new samples while continuing to
  reuse already admitted samples.
- Omit an entire sample exceeding the verified 65,535 encoded-byte per-sample
  scope; do not truncate it. It consumes no slot, so later samples that fit can
  still be admitted.
- Playbacks referring to omitted samples become rests, preserving song end and
  loop positions.
- If all PCM is omitted, generate the remaining FM MML without requiring an empty
  PDX.

65,535 bytes is the currently verified projection scope, not the PDX format's
intrinsic limit. It also differs from MUCOM's 256 KiB bank limit; no 256 KiB total
capacity limit is added here. Source IR analysis and generation needed for final
clock alignment still run, so force does not necessarily shorten conversion time.

Capacity omission is distinct from normalization's short-gate omission. `--force`
permits the explicitly listed capacity omissions, not every unverified operation
or semantic loss. Known PCM transcoding losses still require
`--pcm-policy best-effort`.

## Lists and diagnostics

The post-conversion console and TXT report list ports, register numbers, affected
bits, actions, and reasons, including omitted part names such as PSG1, SSG3, and
FM3. `write` denotes a write, `interval` an interval, and `part` an entire part.
Counts are evaluations after loop expansion, not equivalent source-write counts.
Event IDs, loop iterations, and original timestamps present in source Segments
are retained. PSG Segments without that information use blank fields plus the
original row and timestamp; values are not invented.

The cause of a muted interval can have been set before the write that starts the
interval. Diagnostic `register` identifies the affected function;
`trigger_register` identifies the write that delimited the interval. Omitting a
whole register is distinct from omitting the effect of some of its bits.

- `<stem>.opna_force.skipped_registers.csv/.json`: all OPNA decisions and their
  aggregate list.
- `<stem>.psg_force.skipped_registers.csv/.json`: omitted intervals and aggregate
  list for the standalone PSG route. Missing source event IDs remain blank;
  original Segment rows and timestamps are recorded.
- `<stem>.opna.unmodeled.csv`: evidence of uninterpreted source writes.
- `<stem>.opna_ssg.segments.csv`: unchanged source SSG Segments.
- `<stem>.opna_ssg.omissions.csv/.json`: omitted SSG intervals.
- `<stem>.opna_fm.omissions.csv/.json`: unprojected register writes.
- `<stem>.pcm.force_capacity.csv/.json`: sample/playback IDs, capacity reasons,
  actual/limit, original times, and admission/omission decisions.
- `<stem>.opna-opm.json` and `.conversion.json`: `force_projection`, under
  `projection_settings` in the latter.

Detailed CSV/JSON files for listening exports are under `_diagnostics`; the
TXT intended for distribution is under `tracks/<stem>/`. Omitted durations of
simultaneous channels may overlap: their sum is not a reduction in song length.
Successful generation does not guarantee audio identity or physical playback.

## Compiler

Automatic workarounds for compiler limits are deferred at this checkpoint.
Compilation failure is not reported as success even with `--force`. Generated
MML, PCM IR, and diagnostics are retained and the error is reported.

Channel-allocation policy without force is unchanged. OPNA's existing FM-priority
allocation and omission of excess SSG parts remain in the allocation diagnostics.
With force, omitted part names are also grouped in the register list.
