# C140 全パート再生（ミックス方式）と PCM/OPM レベル校正 — 実装仕様

対象: x68k_vgm2mml、C140 経路（codex/c-140 ブランチ）
位置づけ: 大規模変更。Codex がユーザー環境で実装し、検証・ブラッシュアップは別途行う。

## 1. 目的と背景

- Burning Force 03 では PCM 8トラック上限により 2,682 ゲート中 694 件が脱落する。
  今回の最優先は「ミックスしてでも全パートを鳴らす」こと。
- これは 2026-10-25 の C140 実装で決めた「whole-song mix fallback はしない」
  という方針の**見直し**である。見直す理由は次の2点。
  - 全パート再生が最優先事項になった。
  - PCM バッファ 1200KB は FDD (2HD 1.2MB) に収めるための線であり、
    現在は設計の律速ではない。小さいに越したことはないが、サイズ削減を
    理由に再生を犠牲にしない。
- PCM の音量が OPM と比べて非常に大きい。MAME の Namco System 2 構成では
  C140 ルート 0.75 / YM2151 0.80 とほぼ同等で、基板側に大きな意図的
  オフセットはない。変換側の校正誤差として扱う。
- この作業で得る PCM ハンドリング（ミックス、チャンク化、共有化、レベル
  校正）の知見は、将来 mucom88_vgm2mml の OPNA Delta 系や MSX 側へ
  反映する前提。C140 専用の場当たり実装ではなく、共通部品として作る。
  なお MSX 側の ADPCM 環境（ターボR、Y8950、OPL4、Makoto カートリッジの
  OPNA）ではサンプルデータは 256KB が上限の目安になる。共通部品は
  MB 級バッファを前提にせず、256KB 級でもチャンク化・共有化が効く
  設計にしておく。

## 2. スコープ

- 変更対象は C140 経路と、そのために必要な共通 PCM 部品。
- SegaPCM / MSM6295 / OPNA PCM / PSG の各経路の変換結果は変えない。
  共通部品に手を入れる場合は既存テストで不変を確認する。
- 受け入れ対象曲は Burning Force 03（密な曲）。レベル校正の検証には
  疎な曲をもう1曲使う。

## 3. ミックス方式

- C140 の全声部を、ピン留め済み libvgm c140.c オラクルと一致する
  ネイティブ軌跡どおりにレンダリングし、ターゲット波形を作る。
- 配置はまずフルミックス mono 1本、または stereo 2本（L/R ミックス）。
  チャンク分割（一定 tick 窓）・各チャンクの独立エンコード・順次トリガ・
  曲ループの型は PSG 波形経路（pcm_waveform_mdx）の既存方式を再利用する。
- チャンクのバイト完全一致による共有化を行う（バンク機械の同一性判定を
  チャンクに適用する）。ループ周回・繰り返しフレーズの重複を1回分に
  するのが目的。サイズは証跡に記録するが、合否の律速にはしない。
- ミックスに含めた声部をバンク配置にも載せて二重再生しない（disjoint）。
  将来、一部声部をバンクに分離する場合もこの原則を守る。
- ADPCM のチャンク境界は独立エンコードで predictor 状態を完結させる。
  符号化済みバイト列の途中接続（スプライス）はしない。
- 曲ループの継ぎ目を跨ぐ音を、再スタートに見せかけない。既存の
  target guard の原則を維持し、表現できない場合は明示的にブロックする。

## 4. レベル校正

- 基準はピン留め libvgm によるレンダリング。曲ごとに C140 と YM2151 の
  RMS 比を基準比として測る。
- 変換側でも PCM デコード済みミックスと OPM 側の RMS 比を測り、
  基準比との差分を C140 経路の target_volume 導出への一括オフセット
  （再生側）として適用する。
- サンプル bytes の焼き直しでバランスを直さない。÷510 の単体校正は維持。
- オフセット値は証跡に残し、曲ごとに自動で変わるような fitted な
  値にしない（代表曲で決めた定数を経路の定数とする）。

## 5. 維持する不変条件（field_notes 由来）

- gate はアタックではない。保持中のアドレス・音量・レート変更は
  継続軌跡として保持する。
- Raw / State / Segments の段階分離と中間成果物の保存。
- 表現できない入力は無音化して成功扱いにせず、明示的に診断する。
- サンプルの同一性はバイト完全一致で確定する。

## 6. 実装順序

1. C140 ネイティブミックスレンダラ（オラクルとの一致確認まで）。
2. 波形経路への接続（チャンク化・配置・ループ）。BF03 で脱落ゼロ。
3. チャンク共有化。
4. レベル校正オフセットの導出・適用。密な曲と疎な曲で検証。

## 7. 受け入れ基準

- BF03: 省略 0 件（全 2,682 ゲートが音として存在する）、MDX コンパイル
  成功。MXDRV ロード時にトラックバッファ不足が出ないことはユーザーの
  再生確認で判定する（過去に発生した未解決の観測事項）。
- レベル: 変換後の PCM/OPM RMS 比が基準比の ±1.5 dB 以内（目安。
  実装時に代表曲の実測で確定する）。
- 既存テスト: C140 関連と export 関連が全て通る。他経路の出力は不変。
- 結果は field note に残す。うまくいかなかった案も同様に残す。
