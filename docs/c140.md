# C140 to PCM8 sample-bank projection

C140 System 2 (type 0) and System 21 (type 1) VGM sources now use native
source analysis followed by the existing MDX/EX-PDX bank target. Input may be
C140 alone or OPM+C140. ASIC219/type 2, dual C140 and unknown register/range
variants are retained as source evidence and explicitly rejected for projection.
OKIM6295 support is a separate future source adapter.

## Usage

```sh
python scripts/export_mdx.py INPUT.vgm --outdir outputs/c140
```

The existing defaults apply: mmlx, FM state 24 ms, normalization 8 ms, timeout 1200,
EX-PDX and budget96 reduction. Auto PCM policy selects best-effort for C140
transcoding and records c140_bank_transcoding. Explicit strict still rejects
known losses. Native direct MSM6258 and existing DAC/PSG policy rules are unchanged.

```sh
python scripts/export_mdx.py INPUT_DIRECTORY --outdir outputs/c140 --force
```

Force can omit excess PCM voices with source-linked diagnostics. It cannot
repair missing ROM or unknown chip semantics. Source C140 analysis retains all
24 voices; target PCM8 has 8 simultaneous voices. No automatic whole-song mix
fallback is used. The existing standard/low/ultra_low profiles, single 96-slot
bank, 1,200,000-byte PDX budget and per-sample format limits remain target rules.

## Source evidence

py/c140.py uses the shared 44,100 Hz VGM traversal, preserving ordered writes,
original event IDs and loop occurrences, ROM blocks and coverage, source State
and write-observed Segments. Segments describe controls, not independently
observed audible attacks. Zero register/Key-Off initialization is explicitly a
reference reset assumption, not an observed source write.

The pinned runtime profile is libvgm bad50c571db45b872304bdcd0603dd2214f0663e:

- Start/end/loop addresses latch on each Key-On write. Repeated same-value
  Key-On remains a retrigger.
- Frequency, bank, volume and format/loop controls follow the reference's
  live-register semantics. Controls preserve fractional cursor/interpolation.
- Zero frequency pauses advancement without Key-Off. Silent gain does not stop
  address advancement.
- Natural exhaustion, explicit Key-Off, retrigger and source EOF are distinct.
- VGM loop traversal carries chip/voice/ROM state; it does not reset oscillators.
- Linear signed PCM and C140's custom compressed table are distinct codecs;
  compressed C140 data is not decoded as generic G.711.

Raw C140 clock metadata is retained. Legacy 21390 becomes 12288000; other
positive sub-1MHz values use the pinned player's 576 compatibility rule. The
native reference runs at floor(effective_clock/288), with its float32 frequency
factor. Source write scheduling applies commands before the next native frame.

## Bank projection

py/c140_bank.py renders individual voices with persistent playback state.
Stable one-shots use complete reusable waveforms when the optional tail is
available and within a separate completion budget; otherwise they retain the
validated observed gate. Completion is cached independently of onset gain/pan.
Stable internal-loop captures
can share equal finite waveforms. Onset volume/pan do not create new stable
assets. Held control/ROM changes use finite trajectory variants, with gains
baked once and full target onset gain. Such variants are not described as
recovered ROM instruments. Native event/source links remain available after
deduplication and the common similarity/96-slot reduction.

Target output is mono MSM6258 ADPCM with fixed half-scale waveform headroom,
resampling/requantization and quantized PCM8 onset volume. Unequal stereo gains
are approximated; held stereo variants are centered. These are recorded losses,
not physical waveform equivalence. Source pitch/rate is preserved in native
state; rate-dependent target variants may be required.

The packer does not add sample-loop or arbitrary-seek support to MDX. Internal
loops are captured over the observed finite voice duration. A held voice across
a song-loop seam may be rejected by the existing PCM continuation guards;
--no-song-loop requests one finite pass. Independent PDX decoder resets and
resident-driver acoustic gain remain unverified.

Resource limits are explicit before capture/resampling: 64 MiB ROM,
4 million native frames per gate, 48 million captured native frames overall,
a separate 32 million native-frame completion budget,
and 16 million unique target samples. Completion keeps one reusable ROM snapshot.
Missing ROM bytes are never replaced by
invented silence or FF. A source/resource rejection is separate from slot,
voice, byte-budget and native playback-memory outcomes.

Playback rows retain initial bank/frequency/codec, latched ranges, ROM generation
and original source events. Source files are not rewritten. Private ROM-derived
artifacts remain only under ignored output directories.

## Validation

Public fixtures under tests/fixtures/public/opm_c140 are newly authored
arithmetic waveforms/register sequences. Regenerate using
python tests/scripts/generate_c140_public_fixtures.py.

Optional independent oracle setup and self-test:

```sh
python scripts/c140_reference.py --setup --self-test
python -m unittest discover -s tests/scripts -p 'test_c140*.py' -v
```

The setup keeps the unchanged pinned external C core/source under ignored
.tools/c140-reference and records hashes. Exact authored comparisons cover
System 2/21, custom compression, natural/internal loop ends, repeated Key-On,
held controls, zero-frequency pause, silent continuation, scheduler boundaries
and interpolation state. They verify the source runtime, not audible MDX
playback. Compilation and listening remain separate validation dimensions.
